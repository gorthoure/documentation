# Получение и обновление данных контента Амедиатеки

## Примечания

В БД есть колонки для контроля контента, автоматически они не обновляются. 

Автоматически только проверяется доступность на амедии и если тайтл недоступен - ставится дата закрытия предыдущим днём,
либо дата которую отдаёт сама амедия по закрытию прав.

- is_active - доступность в принципе для всех порталов
- active_портал - доступность для конкретного портала.

т.е. если надо закрыть для какого-то одного портала ставим 0 в active для конкретного портала, если надо для всех - ставим 0 в is_active

### Функция `getStudios`

#### Описание

Выполняет запросы к API Amediateka для получения информации о студиях.

#### Этапы выполнения

1. Отправка GET-запроса:
    - для фильмов: `catalogue_type=movies`
    - для сериалов: `catalogue_type=series`
2. Обработка ответа
3. Сохранение данных в таблицу `studios`
    - `studio_name` — Название студии
    - `amedia_id` — ID студии из Amediateka
4. Обработка ошибок при вставке в базу данных

### Функция `getFilms`

#### Описание

Загрузка всех фильмов с платформы Amediateka с использованием API. Каждый фильм проверяется на доступность для региона TJ, сохраняется в базу данных и связывается с сопутствующими данными (жанры, студии, страны, персоны).

#### Обработка каждого фильма полученного по API

1. Получение полной информации о фильме через метод getFilmMetaData

2. Сохранение данных:

   * Основные метаданные фильма вставляются или обновляются в таблице films.

   * Связанные сущности (жанры, страны, студии, персоны) привязываются через linkFilm().

3. Пропускаются:

   * Фильмы, не найденные на платформе.

   * Фильмы, не доступные в Таджикистане.

---

### Функция `getFilmMetaData`

#### Описание

Отправляет GET-запрос к API Amediateka для получения полной информации о фильме по его `film_id`. Полученные данные обрабатываются и сохраняются в виде метаданных, а также сохраняются эпизоды и рекомендации фильма в соответствующие таблицы базы данных.

Параметры

| Параметр  | Тип   | Описание                          |
|-----------|-------|-----------------------------------|
| `film_id` | mixed | Идентификатор фильма в Amediateka |

#### Возвращаемое значение

1. Массив с двумя ключами:

   * metadata: ассоциативный массив с метаданными фильма

   * other_info: массив связанных сущностей (страны, жанры, студии, персоны)

2. Или строка, если фильм недоступен в Таджикистане

#### Алгоритм работы

1. Проверка доступности фильма для Таджикистана (TJ)

2. Формирование метаданных:

   * Название, оригинальное название
   * Год, 
   * возрастной рейтинг, 
   * описания
   * Оценки (IMDb, Кинопоиск, Amediateka)
   * Изображения (разные форматы)
   * Дата публикации и окончания прав
   * Трейлеры

3. Обработка эпизодов (если это многосерийный фильм), сохраняются в таблицу film_episode

4. Обработка рекомендаций, сохраняются в таблицу films_recommendations


#### Пример возвращаемых данных
```php

[
    'metadata' =>   [
                        'film_id' => 12345,
                        'film_name' => 'Название',
                        'film_name_original' => 'Original Title',
                        'ratingKinopoisk' => 7.5,
                        'ratingImdb' => 7.3,
                        ...
                    ],
    'other_info' => [
                        'countries' => [...],
                        'genres' => [...],
                        'studios' => [...],
                        'persons' => [...],
                    ]
]
```

### Функция `getSerials`

#### Описание
Получает список сериалов с платформы Amediateka через API и сохраняет их метаданные, связанные данные и информацию о сезонах в базу данных.

#### Описание логики

1. Для каждого сериала вызывается метод getSerialMetaData для получения данных о сериале.

2. Для каждого сериала вызывается метод getSerialSeasons для получения и записи данных о сезонах сериала

3. Сохранение данных:

   * Основные метаданные сериала вставляются или обновляются в таблице films.

   * Связанные сущности (жанры, страны, студии, персоны) привязываются через linkFilm().

4. Пропускаются:

   * Сериалы, не найденные на платформе.

   * Сериалы, не доступные в Таджикистане.

5. Запись в таблицу films с флагом is_serial

### Функция `getSerialMetaData`

#### Описание

Получение метаданных о сериале по его ID с платформы Amediateka через API. Данные сериализуются в массив и сохраняются в локальную базу данных, включая рекомендации, изображения, рейтинги и дополнительные данные.

#### Параметры

| Параметр | Тип | Описание              |
|----------|-----|-----------------------|
| `ser_id` | int | ID сериала Амедиатеки |



#### Описание логики

1. Получение данных о сериале по его ser_id.

2. Формирование метаданных:

   * Название, оригинальное название, рейтинги (Кинопоиск, IMDb, Amediateka), возрастные ограничения, год премьеры и дата публикации.

   * Изображения: горизонтальные, вертикальные, баннер, логотипы, трейлер.

   * Флаг is_serial = 1 указывает, что это сериал.

3. Изображения:

   * Приоритеты выбираются по наличию: partnersPoster_16_9, затем productPoster, затем HproductBackground.

4. Каждая рекомендация сериалу сохраняется в таблицу films_recommendations.

#### Возвращаемое значение
1. Массив с тремя ключами:

   * metadata: ассоциативный массив с метаданными сериала

   * seasons: ассоциативный массив с сезонами сериала

   * other_info: массив связанных сущностей (страны, жанры, студии, персоны)

2. Или строка, если фильм недоступен в Таджикистане

###  Функция `getSerialSeasons`

#### Описание

Функция получает данные о сезонах сериала и эпизодах из API Amediateka. Для каждого сезона собираются его метаданные и информация об эпизодах, после чего эти данные сохраняются в базу данных.

#### Параметры

| Параметр  | Тип   | Описание                                                                      |
|-----------|-------|-------------------------------------------------------------------------------|
| `ser_id`  | int   | ID сериала Амедиатеки                                                         |
| `seasons` | array | Массив данных о сезонах, каждый элемент которого содержит информацию о сезоне |


#### Описание логики

1. Получение данных о сезоне:
   * Для каждого сезона из массива $seasons делается запрос к API Amediateka для получения метаданных, используется season['id']

   * В ответе из API ожидаются данные о сезонных метках, рейтингах, изображениях и эпизодах.

2. Метаданные сезона:

   * Полученные данные о сезоне включают: описание сезона, название, номер сезона, количество эпизодов, изображения и рейтинги (Kinopoisk, IMDB, Amediateka).

   * Эти данные сохраняются в таблицу seasons, а также сохраняются ссылки на изображения и рейтинги.

3. Обработка эпизодов:

   * Если в сезоне есть эпизоды, для каждого эпизода делается запрос к API и сохраняется информация о серии: название, номер серии, продолжительность, дата выхода и изображение.

   * Эпизоды сохраняются в таблицу series.

#### Пример входных данных массива seasons
```php
[
   [
      'id' => 12345,
      'title' => 'Season 1',
      'seasonNumber' => 1,
      'episodeCount' => 10,
   ],
   [
      'id' => 67890,
      'title' => 'Season 2',
      'seasonNumber' => 2,
      'episodeCount' => 12,
   ]
   ...
]
```

###  Функция `linkFilm`

#### Описание

Функция связывает фильм/сериал с жанрами, странами, студиями и персонами.

#### Параметры

| Параметр  | Тип   | Описание                                                            |
|-----------|-------|---------------------------------------------------------------------|
| `film_id` | int   | ID фильма Амедиатеки                                                |
| `info`    | array | Ассоциативный массив с ключами: genres, countries, studios, persons |

#### Описание логики
1. Обработка жанров (genres):

   * Для каждого жанра ищется его ID в таблице genres по amedia_id.

   * Если найден — создаётся связь в таблице films_genres.

2. Обработка стран (countries):

   * По аналогии с жанрами — формируется связь в films_countries.

3. Обработка студий (studios):

   * По аналогии с жанрами — формируется связь в films_studios.

4. Обработка персон (persons):

   * Персона сначала добавляется (или обновляется) в таблицу persons.

   * Затем формируется связь в films_persons.

# Проверка и обновление данных о доступности контента (Job story 2)

## Проверка и обновление данных о доступности фильмов/сериалов (файл `checkFilms`)

### Описание

Скрипт проверяет актуальность прав на фильмы и сериалы в базе данных, делая запросы к API Amediateka и обновляя поле `right_end_date` в таблице `films`.

### Алгоритм выполнения

1. Получает список фильмов из таблицы `films`.
2. Для каждого фильма делает запрос к внешнему API Amediateka.
3. Проверяет наличие прав для региона "TJ" (Таджикистан).
4. Обновляет поле `right_end_date` в базе данных в зависимости от наличия прав.
5. Обновляет поле `info_text` если значение поля `update_description` равно 1

### Примечания

Поле right_end_date обновляется на:

- вчерашнюю дату, если доступ в TJ отсутствует;
- вчерашнюю дату, ошибке в API (message в ответе)
- дату окончания лицензии из API, если она присутствует.

**Если right_end_date уже установлен, скрипт всё равно может его обновить, если в API изменились данные.**

## Проверка доступности трейлеров (файл `checkTrailers`)

### Описание

Скрипт проходит по всем фильмам в таблице `films`, проверяет значение поля `trailer` и, если оно пустое или указывает на несуществующий ресурс, устанавливает его в `NULL`.

### Алгоритм выполнения

1. Получает список фильмов из таблицы `films`.
2. Для каждого фильма делает запрос к внешнему API Amediateka.
3. Проверяет наличие данных в поле `trailer` в ответе от API.
4. Если поле пустое - обновляет строку в таблице, устанавливает в null значение поля `trailer`.
